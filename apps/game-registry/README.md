# game-registry

The BNB game server registry (`bnb-game-servers/registry`, Go + Postgres): game servers register here for a join code and a place in the server list, and the playground posts match results and records to it for its leaderboards.

- URL: `https://game-registry.kblab.me` (LAN and tailnet only). In the cluster: `http://game-registry.game-registry.svc:8080`.
- Image: `git.kblab.me/kblack0610/bnb-game-servers/registry:<tag>`, published by that repo's Forgejo workflow on a `registry-v*` tag. Bump the tag in `deployment.yaml`. Since v1.5.0 the admin site also has a Live players page (`/playground/live.html`): servers that register with `admin: true` long-poll the public port for admin lines (`GET /api/v1/servers/{id}/admin/next`, held up to 30 s, under Traefik's 60 s default).
- Tokens: `tokens-secret.yaml` (sops). `SERVER_TOKEN` is for dedicated servers, and its results move ratings; `playground-server` holds a copy in its own namespace (`apps/playground-server/registry-token-secret.yaml`), so rotate both together. `HOST_TOKEN` ships in every playground build (`Assets/Playground/Resources/Online/online.json`) and only registers servers and posts unverified results.
- Data: since v1.8.0, the database `registry` on the shared Postgres (`apps/postgres/registry-db-bootstrap-job.yaml`) and snapshot bodies (worlds and characters) in the MinIO bucket `game-saves` (`apps/minio/game-saves-bucket-job.yaml`, versioned, noncurrent versions expire after 30 days). `saves-secret.sops.yaml` holds `DATABASE_URL`, the bucket keys and `ACCOUNT_PEPPER`. The database password is also in `apps/postgres/registry-db-secret.sops.yaml` and the bucket keys in `apps/minio/game-saves-secret.sops.yaml`, so rotate each pair together. Never rotate the pepper: it hashes every player code, and a new one signs every account out for good.
- The `import-sqlite` init container copied the v1.7.0 SQLite file from the `game-registry-data` volume once. It and the volume go away in a follow-up, once the import is verified.
- Backup: `game-saves-backup` (`backup-cronjob.yaml`, 02:50 nightly) dumps the database and mirrors the bucket to the NAS, `backups/home-k3s/game-saves/`. Restore: `docs/backup-runbook.md`, "Restore the game registry".
- Routes and env: `registry/README.md` in bnb-game-servers.
- Admin site: `https://games.kblab.me/playground/` (the registry's port 8081, `ingress-admin.yaml`). It edits each playground game's live overrides on the dev and prod channels. Sign in with Forgejo (OAuth2 app id 6, `games.kblab.me/playground`); only the logins in `ADMIN_USERS` (`deployment.yaml`) get in. Secrets are in `admin-secret.yaml` (sops): the OAuth app, the session key, and `ADMIN_TOKEN`, which the playground's catalog workflow uses (a GitHub Actions secret there too, so rotate both together). Save to repo stays off until `BAKE_GITHUB_TOKEN` is added to that secret: a GitHub fine-grained token with Actions read and write on `BlackNBrownStudios/unity-core-playground` and nothing else. How it works: `docs/operations/admin-site.md` in the playground.
- Fleet page: `https://games.kblab.me/playground/fleet.html` (since v1.7.0; `games.kblab.me/` redirects there). Every live server by its session id (`<yymmdd>-<game>-<provider>-<n>-<site>`), the home servers listed and scaled through zomboid-control (`CONTROL_API`, token in `control-token-secret.yaml`, a third copy of `apps/zomboid/control/secret.yaml`), online games on Edgegap, and a searchable history of ended sessions.
- Metrics: `/metrics` on port 9090 (`servicemonitor.yaml`, no ingress), one series set per live session with its heartbeat stats; the Game fleet dashboard is `apps/monitoring/dashboards/game-fleet.json`, linked per session from the Fleet page (`GRAFANA_URL`, `LOGS_URL`).
