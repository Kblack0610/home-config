# Standards

The invariants this repo holds, one per line with its why and the check that fails when it breaks. Repo-wide working rules (worktrees, host naming, LLM routing, secrets) are in [../CLAUDE.md](../CLAUDE.md); the rules every project shares are in the global `~/.claude/CLAUDE.md` and are not restated here. CI is `.forgejo/workflows/checks.yaml`, and a check belongs there only when two things must agree, not when a file should merely be tidy.

- Push to `forgejo`, never to `origin`, and never open a PR on GitHub. Why: Flux reconciles from forgejo only, and the mirror force-overwrites GitHub's master on the next push, so a merge made there never deploys and then disappears ([gitops.md](./gitops.md#canonical-remote)). Check: `.github/workflows/reject-pull-requests.yml` closes a PR opened on GitHub.
- Every `apps/` change deploys through Flux: edit, commit, push, reconcile; never `kubectl apply` a Flux-managed resource. Why: a direct apply is silently overwritten on the next reconcile or blocks it ([gitops.md](./gitops.md)). Check: the `kustomize-builds` job builds `apps` and each `clusters/*/` entry point, the same set Flux builds; nothing detects a direct apply.
- Host-OS services go through an Ansible role bound in `ansible/playbooks/site.yml`, never a hand-written unit over SSH. Why: anything below the kubelet has to be replayable on a rebuilt host ([ansible.md](./ansible.md)). Check: the `convergence-check` CronJob in `apps/ansible-runner/` runs the playbook with `--check --diff` daily.
- SOPS + age is the only secret store, and every `*.sops.yaml` carries a `sops:` block with a `mac:`. Why: a second store (ansible-vault) meant two edit commands and a password file on every workstation, and a file saved in plain text under a SOPS name looks encrypted. Check: `scripts/check-secret-store.py`.
- No slicer profile under `apps/orcaslicer/` holds a printer access code or serial. Why: the repo is public on GitHub and OrcaSlicer writes the live code into any preset you save. Check: `scripts/check-secret-store.py`, with a planted-code negative control in `checks.yaml`.
- A Home Assistant package, dashboard or custom sentence file is listed in both `apps/home-assistant/kustomization.yaml` and the init container's copy list. Why: a file missing either edit is committed and reviewed but never reaches `/config`, and nothing errors. Check: `scripts/check-ha-packages.py`.
- Every machine in a fleet roster is declared in the gatus config. Why: a machine retired from one copy of the roster showed as a red dot, identical to a machine that is down. Check: `scripts/check-fleet-roster.py`.
- The runner roster in `apps/github-runner-exporter` matches the slot counts in `ansible/inventory.yml`, in both directions. Why: the exporter's denominator is written down independently of the GitHub API, so an unrostered pool reads healthy and a retired one reads permanently short. Check: `scripts/check-runner-roster.py`.
- A `PrometheusRule` carries the label `release: kube-prometheus-stack`. Why: without it the rule applies cleanly and is never evaluated, with no error anywhere. Check: none in CI; confirm Prometheus loaded the group through `/api/v1/rules`.
- Alert rules are unit-tested with promtool. Why: a threshold or `for:` nobody exercised pages at the wrong time or never. Check: `scripts/test-prometheus-rules.sh`, which lists each rule file it covers, so a new `prometheus-rules-<name>.yaml` adds its name there and a `tests/<name>.test.yaml`.
- A directory under `apps/` that Flux does not reconcile gets a row in [excluded-from-flux.md](./excluded-from-flux.md) in the same PR. Why: the `kustomize-builds` job gates only what Flux builds, so an unlisted directory is neither deployed nor explained. Check: none; review.
- Anything that needs a self-hosted model calls the LiteLLM gateway with a scoped virtual key, never a host IP and port. Why: a stale endpoint failed closed to a default and degraded triage silently ([../CLAUDE.md](../CLAUDE.md)). Check: none; review.
